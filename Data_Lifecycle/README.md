# Data Lifecycle: Finite State Transition tools

Tools for describing the Data Lifecycle as a Finite State Transition (FST) model of a Data Asset rather than a linear sequence of stages. A stage becomes a state with a contract: conditions to enter, conditions to remain (invariants), permitted activities, conditions to leave, and guarded, authorised transitions. Knowledge Areas are orthogonal state machines that contribute guards and evidence to the global transitions.

This folder is public and holds **no model data**. Models live in a private store and are loaded into the viewer at runtime.

## Contents

- `fts_viewer.html`: single-file, offline viewer. Open it in a browser. Under GitHub settings, give it the owner, repository, branch and the `models` folder of the private repo, plus a fine-grained token limited to that repository with Contents: read-only; Load from GitHub then reads every `.fts.json` in that folder (the Global FTS and each Knowledge Area FTS). The token and settings stay in that browser and are sent only to api.github.com; Forget token removes it, and it should be revoked in GitHub as well. Alternatively, Load models folder reads the same folder from disk. Loaded models appear in the bar at the top and you switch between them; the set is remembered in the browser and reloaded from GitHub on the next open while a token is saved. Where a Knowledge Area model contributes guards to a Global transition (by transition ID), the Global transition's contract shows them, labelled with the contributing model. Tabs: Contrast, State map, UML state diagram, Simplified FTS, Transitions (the full eligibility and authorisation contract per transition), Knowledge Areas, Rules. The Simplified FTS tab draws the same machine with complexity removed, after Harel's clustering and the super-state / sub-state guidance: collapse Global States to single boxes or open them one level, replace transition and activity wording with short codes (T, E, G, A) explained in a generated legend, show or hide contracts, guard counts, events, effects, rework loops, readiness states and notes, and focus on one composite, one state's neighbourhood, or the path from the start to a chosen state. The UML tab draws the model in standard UML state machine notation (initial pseudostate, composite states, entry / do / exit compartments, invariant constraints, event [guard] / effect transition labels) plus the Composite Data Management State as orthogonal regions; the Mermaid source can be copied for a document and the diagram downloaded as SVG. The Mermaid renderer (MIT) is inlined so the file works offline. Nothing is uploaded anywhere. On the Simplified, UML and State map tabs an FTS selector switches between the Global protocol and each loaded Knowledge Area; every FTS (region) starts collapsed to a single box and one click on the box expands it (click the frame again to collapse); the region chips, expand all and collapse all do the same; full screen, zoom (buttons, ctrl+wheel) and drag pan apply to the pane; the collapse state is remembered per model while the page is open (viewer v0.13).
- `tools/convert_fts.py`: converts a DMBOK State Transition metadata workbook (the 27-sheet format) into the `.fts.json` model. Usage: `python convert_fts.py <workbook.xlsx> <out.fts.json>`. Requires `openpyxl`.
- `schema/fts_model.md`: the model shape the viewer reads and the skill populates.

## Versioning

The viewer carries its version and build date and time (SAST) in the header and footer. A model carries its own version, status and build stamp in `meta`.
