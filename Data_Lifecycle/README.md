# Data Lifecycle: Finite State Transition tools

Tools for describing the Data Lifecycle as a Finite State Transition (FST) model of a Data Asset rather than a linear sequence of stages. A stage becomes a state with a contract: conditions to enter, conditions to remain (invariants), permitted activities, conditions to leave, and guarded, authorised transitions. Knowledge Areas are orthogonal state machines that contribute guards and evidence to the global transitions.

This folder is public and holds **no model data**. Models live in a private store and are loaded into the viewer at runtime.

## Contents

- `fts_viewer.html`: single-file, offline viewer. Open it in a browser. Under GitHub settings, give it the owner, repository, branch and the `models` folder of the private repo, plus a fine-grained token limited to that repository with Contents: read-only; Load from GitHub then reads every `.fts.json` in that folder (the Global FTS and each Knowledge Area FTS). The token and settings stay in that browser and are sent only to api.github.com; Forget token removes it, and it should be revoked in GitHub as well. Alternatively, Load models folder reads the same folder from disk. Loaded models appear in the bar at the top and you switch between them; the set is remembered in the browser and reloaded from GitHub on the next open while a token is saved. Where a Knowledge Area model contributes guards to a Global transition (by transition ID), the Global transition's contract shows them, labelled with the contributing model. Tabs: Contrast, State map, UML state diagram, Simplified FTS, Transitions (the full eligibility and authorisation contract per transition), Knowledge Areas, Rules. The Simplified FTS tab draws the same machine with complexity removed, after Harel's clustering and the super-state / sub-state guidance: collapse Global States to single boxes or open them one level, replace transition and activity wording with short codes (T, E, G, A) explained in a generated legend, show or hide contracts, guard counts, events, effects, rework loops, readiness states and notes, and focus on one composite, one state's neighbourhood, or the path from the start to a chosen state. The UML tab draws the model in standard UML state machine notation (initial pseudostate, composite states, entry / do / exit compartments, invariant constraints, event [guard] / effect transition labels) plus the Composite Data Management State as orthogonal regions; the Mermaid source can be copied for a document and the diagram downloaded as SVG. The Mermaid renderer (MIT) is inlined so the file works offline. Nothing is uploaded anywhere. On the Simplified, UML and State map tabs an FTS selector switches between the Global protocol and each loaded Knowledge Area; every FTS (region) starts collapsed to a single box and one click on the box expands it (click the frame again to collapse); the region chips, expand all and collapse all do the same; full screen, zoom (buttons, ctrl+wheel) and drag pan apply to the pane; the collapse state is remembered per model while the page is open (viewer v0.13). An Inside control on the Simplified and UML tabs lays the states inside each FTS out across the page (the default from v0.15) or down it, and the Wide page button at the end of the tab bar lets the page use the full browser width (remembered in the browser); both re-fit the zoom (viewer v0.14). Fit never shrinks a diagram below 72 percent; when a wide FTS cannot fit the pane width readably it is fitted to the pane depth instead (up to 100 percent, 130 percent in full screen) and the pane scrolls sideways (drag to pan) (viewer v0.16 and v0.17). Hovering a state shows its definition and invariant, hovering a transition label shows the event, guards, decision right and services, and hovering a region title shows its managed element; transition cards also list the permitted activities and the evidence record, state cards the activities permitted in the state (viewer v0.17 and v0.18). The Layout control on the Simplified and UML tabs chooses compact (the ELK layered layout, bundled with Mermaid 11.4.1 from @mermaid-js/layout-elk 0.2.3, MIT; it folds a long chain back on itself so an FTS uses depth as well as width) or linear (Dagre, one straight chain); compact is the default and the choice is remembered in the browser. The single file is about 7.8 MB with ELK inlined (viewer v0.18). From v0.19 the Simplified tab defaults to the viewer's own wrapped layout (`tools/fts_designer/snake_layout.js`): each FTS reads from the top left, left to right, wraps to the next row when the pane width is used up, and rows are justified to the full width; the initial pseudostate sits before the first state; transitions between rows run through lanes below a row and, for non-adjacent rows, a channel at the band's left (upward) or right (downward) edge, so no path crosses a state; the layout reflows on resize, Wide page and full screen. Compact (ELK) and linear (Dagre) remain as Mermaid alternatives; the UML tab keeps Mermaid. From v0.20 loading a scenario on the Simulate tab restarts every loaded model from its initial State Vector before the scenario's KA presets are applied, and Reset to initial vector resets all loaded models, so two federated scenarios can be run one after the other in one session without one run's KA states leaking into the next. From v0.21 the Global contributions tab of a Knowledge Area also lists the couplings other loaded models declare against it (the incoming side, derived from every loaded model). From v0.22 a Documentation tab renders the selected model's chapter live from the loaded models, with no server and no extra files: an In one page section (definition, what the Knowledge Area ensures, what it manages, the Global transitions it gates, a context diagram of the Global regions it gates, its managed elements and the Knowledge Areas it is coupled to, whom it depends on, and the drafted decision-right holders still to be confirmed) followed by the full reference (regions and states, transitions, contributions, couplings declared and received, fact bindings, cross-region guards, decision rights, services, events, artefacts, exceptions, roles). On the Global protocol the system book follows the chapter: the model inventory, the Knowledge Area by Global transition matrix and the Knowledge Area by Knowledge Area matrix. Every table and paragraph carries the same element ID as the Word chapters, so a comment made on the page can be quoted against the Word copy. Print or save as PDF opens a print view of the chapter. The Word chapters and system book generated by `tools/fts_designer/fts_docs.py` remain the commentable copies; the tab is the on-screen view of the same content and is only as complete as the set of models loaded (load all models to see the incoming couplings and the matrices in full). From v0.23 the tab has a table of contents on the left (In one page, each region, and every reference section), the whole Knowledge Area drawn with every region expanded under What it manages, one state diagram per region at the top of that region's section (with the region's own transitions beneath it), and a context diagram in which every line starts at a box and ends at a box: each left arrow runs from the managed element whose states a contribution requires to the Global region it gates, and the coupled Knowledge Areas hang off one spine because the model does not record which element a coupling belongs to. The same pages exist as standalone HTML under the private repo's docs/html (one per model, index.html) for reading without the viewer. From v0.24 a Twin tab shows the digital twin: the fleet of Data Asset instances held by the local twin service (`tools/fts_designer/fts_twin.py serve`, standard-library HTTP on 127.0.0.1:8765, no packages to install) or, offline, the files it exports into the private repo's twin/ folder; each instance's Global State Vector, the Knowledge Area regions it has moved, events fired and refused, overrides and holds, with filters by class, Existence state, refused and hold; an instance opened shows every region of every model (shared governing regions read through the element the asset references), the facts the engine derives from the vectors, and the timeline with the guards that refused each refused event and the reason of each override.
- `tools/convert_fts.py`: converts a DMBOK State Transition metadata workbook (the 27-sheet format) into the `.fts.json` model. Usage: `python convert_fts.py <workbook.xlsx> <out.fts.json>`. Requires `openpyxl`.
- `schema/fts_model.md`: the model shape the viewer reads and the skill populates.

## Versioning

The viewer carries its version and build date and time (SAST) in the header and footer. A model carries its own version, status and build stamp in `meta`.
