AI Eval register: recorded vs recomputed

Evaluation integrity rule: a recorded status must never substitute for a computed status. Each row recomputes result (operator) threshold independently; a disagreement is a mismatch, and a recorded pass over a computed fail is critical.

Threshold accepts ≥ 0.90, <= 0.10, 0.80–1.25, = 0 and plain numbers. Non-numeric checks are marked manual and take the status you set.

Eval Requirements

A requirement is generated from a claim, a risk, an obligation or an architecture anchor. It is never generated from a model. Each one carries a typed specification, and its status is computed from the latest run at the moment you read it. Nothing writes a Pass or a Fail into storage.

Five assurance lenses

Lenses are accountability views, not a complete quality taxonomy. The status of each one is derived from the requirements filed under it. There is no RAG button here, because a score typed in by hand is an opinion detached from the underlying tests.
